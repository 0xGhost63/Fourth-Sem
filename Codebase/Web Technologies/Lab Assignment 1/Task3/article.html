Big-O in Plain English

By Hamza Raza · 3 October 2026

Big-O notation describes how the work grows as the input grows, not how fast your laptop is. A loop over n items is O(n). A loop inside a loop over the same items is O(n²).

That gap is invisible with ten items and painful with a hundred thousand. The usual fix is trading a little memory for speed: keep items in a hash map or set, and a lookup that scanned a whole list becomes a near-instant check on average.

Before optimizing anything, measure it. Profile first, find the one hot spot that dominates the runtime, and fix that. Readable code that is fast enough beats clever code nobody can maintain.
